CYBERFORTRESS

Product Requirements Document (PRD)

Project Title: CyberFortress — Interactive Cyber Attack Detection, Simulation & Awareness Platform

Project Type: ICT Semester Project

Academic Program: BS Cybersecurity — First Semester

Team Size: 3 Members

Technology Stack: HTML, CSS, JavaScript, Python Flask, SQLite, Chart.js, Git and GitHub

Document Version: 1.0

---

1. Product Overview

1.1 Introduction

CyberFortress is an interactive cybersecurity educational platform designed to help users understand common cyber threats, experience controlled attack simulations, and learn practical defensive techniques.

The platform combines cybersecurity awareness, interactive demonstrations, security monitoring, and beginner-friendly challenges in one web application.

Instead of simply providing theoretical cybersecurity information, CyberFortress allows users to interact with different cybersecurity tools and understand how attacks happen and how they can be prevented.

1.2 Problem Statement

Cybersecurity threats such as phishing, weak passwords, unauthorized access, and suspicious network activities are becoming increasingly common.

Many beginners understand cybersecurity concepts theoretically but lack opportunities to explore them through practical demonstrations.

CyberFortress addresses this problem by providing a safe, interactive learning environment where users can:

- Recognize phishing attempts.
- Understand attack and defense mechanisms.
- Evaluate password strength.
- Learn about Multi-Factor Authentication.
- Explore security alerts through a Mini SOC Dashboard.
- Test their cybersecurity knowledge through CTF challenges.

1.3 Product Vision

To create a professional, interactive cybersecurity learning platform that makes cybersecurity concepts understandable through practical demonstrations, simulations, and challenges.

1.4 Main Objectives

1. Develop an interactive cybersecurity web application.
2. Educate users about common cyber threats.
3. Demonstrate basic attack detection and defense techniques.
4. Provide practical cybersecurity learning experiences.
5. Integrate frontend, backend, database, and data visualization technologies.
6. Develop a professional portfolio-worthy project.
7. Demonstrate teamwork and practical programming skills.

---

2. Target Users

The primary target users are:

- University cybersecurity students.
- Beginners learning cybersecurity.
- Students interested in ethical hacking and digital security.
- Users who want to improve their cybersecurity awareness.

The platform is designed for educational use and does not require advanced cybersecurity knowledge.

3. Core Features and Functional Requirements

CyberFortress will contain six main modules.

FEATURE 1: Phishing Awareness Simulator

Purpose: Help users identify phishing emails and understand how phishing attacks deceive people.

Functional Requirements

- Display sample phishing and legitimate emails.
- Show sender information, subject, and message content.
- Allow users to identify suspicious messages.
- Provide options to classify an email as phishing or legitimate.
- Display correct or incorrect feedback.
- Explain phishing indicators such as suspicious links, urgency, and misleading senders.
- Calculate the user's quiz score.
- Optionally store quiz results in SQLite.

Expected Outcome

Users should understand how to recognize suspicious emails and avoid common phishing techniques.

FEATURE 2: Attack & Defense Simulator

Purpose: Demonstrate how common cyber attacks happen and how defensive security controls can reduce their impact.

Functional Requirements

- Provide predefined attack scenarios.
- Display attack stages step by step.
- Show simulated attacker and defender activities.
- Allow users to select defensive controls.
- Demonstrate the outcome of applying or not applying a security control.
- Explain the purpose of firewalls, authentication, monitoring, and other defenses.
- Display the final simulation result.

Example Scenarios

- Phishing incident.
- Weak password attack.
- Unauthorized login attempt.
- Basic network intrusion scenario.

Expected Outcome

Users should understand the relationship between cyber attacks, vulnerabilities, security controls, and defensive responses.

All attack scenarios must remain controlled simulations using sample data.

FEATURE 3: Password Security Checker

Purpose: Help users understand password strength and improve their password security practices.

Functional Requirements

- Provide a password input field.
- Include a show/hide password option.
- Evaluate basic password characteristics.
- Check password length.
- Check character variety.
- Identify common or predictable password examples.
- Display a strength indicator.
- Provide recommendations for improving password security.

Expected Outcome

Users should learn how to create stronger, longer, and less predictable passwords.

Passwords entered into the educational checker must not be stored in SQLite or exposed in server logs.

FEATURE 4: MFA Demonstration

Purpose: Demonstrate how Multi-Factor Authentication adds another layer of security to user authentication.

Functional Requirements

- Create a simulated login interface.
- Demonstrate password-based authentication.
- Introduce a second verification step.
- Provide a simulated OTP or verification code.
- Display successful and unsuccessful verification outcomes.
- Explain different authentication factors.
- Compare password-only authentication with MFA.

Expected Outcome

Users should understand how MFA works and why additional authentication factors improve account protection.

The prototype will use predefined demonstration credentials and simulated verification rather than connecting to real accounts.

FEATURE 5: Mini SOC Dashboard

Purpose: Provide a simplified Security Operations Center interface for monitoring and analyzing simulated security events.

Functional Requirements

- Display security event statistics.
- Show a security event log table.
- Display event timestamps.
- Categorize alerts by severity.
- Include alert statuses such as Open, Investigating, and Reviewed.
- Provide event filtering.
- Display charts using Chart.js.
- Show different categories of simulated security incidents.
- Connect event data to SQLite.

Dashboard Components

1. Total security events.
2. High-severity alerts.
3. Reviewed events.
4. Security event table.
5. Event severity chart.
6. Security event category chart.
7. Alert investigation details.

Expected Outcome

Users should understand how security analysts monitor events, identify suspicious activity, and investigate security alerts.

The dashboard will use sample events and events generated by the other CyberFortress simulations. It will not claim to monitor a real network.

FEATURE 6: CyberFortress CTF Challenges

Purpose: Improve users' cybersecurity knowledge through beginner-friendly Capture the Flag challenges.

Functional Requirements

- Display a list of available challenges.
- Provide challenge descriptions and instructions.
- Include different difficulty levels.
- Allow users to submit answers.
- Validate answers through Flask.
- Provide hints and explanations.
- Award points for correct answers.
- Track user progress.
- Store challenge scores in SQLite.
- Optionally provide a leaderboard.

Example Challenges

1. Identify phishing indicators.
2. Password security challenge.
3. Basic Caesar cipher decoding.
4. Security log investigation.

Expected Outcome

Users should improve their cybersecurity knowledge through interactive problem-solving activities.

4. Technology Stack

Frontend

HTML: Provides the structure of the website.

CSS: Controls the visual appearance, layout, colors, and responsive design.

JavaScript: Handles interactive elements, simulations, password checks, quiz logic, and dynamic updates.

Backend

Python: Provides backend programming logic.

Flask: Handles routes, user requests, answer validation, and communication between frontend and database.

Database

SQLite: Stores appropriate information such as quiz results, CTF scores, and simulated security event records.

Data Visualization

Chart.js: Creates interactive charts and graphs for the Mini SOC Dashboard.

Version Control

Git: Tracks code changes and supports development collaboration.

GitHub: Hosts the project repository and supports team collaboration.

5. System Architecture

The system will follow a simple three-layer architecture.

Layer 1: Presentation Layer

HTML, CSS, JavaScript.

Responsible for:

- User interface.
- Navigation.
- Forms and buttons.
- Interactive simulations.
- Dashboard visualization.

Layer 2: Application Layer

Python and Flask.

Responsible for:

- Processing requests.
- Validating user submissions.
- Managing simulation logic.
- Calculating scores.
- Communicating with SQLite.

Layer 3: Data Layer

SQLite.

Responsible for:

- Saving quiz results.
- Saving CTF scores.
- Storing simulated security events.
- Maintaining appropriate application records.

Chart.js will visualize the processed security-event information in the frontend.

10. Non-Functional Requirements

CyberFortress should satisfy the following quality requirements:

1. Usability: Beginners should understand the interface without advanced technical knowledge.
2. Performance: Pages and basic interactions should respond smoothly.
3. Reliability: The application should handle invalid inputs without crashing.
4. Security: Input validation and safe data-handling practices must be followed.
5. Maintainability: Code should be organized into understandable files and modules.
6. Compatibility: The application should support modern desktop and mobile browsers.
7. Scalability: Additional educational modules should be possible in future versions.

11. Project Scope and Limitations

Included in the project

- Six interactive cybersecurity modules.
- Simulated attack and defense scenarios.
- Password security evaluation.
- Simulated MFA.
- Mini SOC monitoring dashboard.
- Beginner CTF challenges.
- SQLite database integration.
- Educational feedback and scoring.

Not included in the initial version

- Real-world network intrusion detection.
- Actual penetration testing against external systems.
- Real phishing campaigns.
- Production authentication services.
- Live threat intelligence feeds.
- Enterprise-grade SOC infrastructure.

These can be considered future improvements if the team has sufficient time and resources.
